# Бункер: Благовещенск

Готовый исходный проект Telegram-бота для социальной игры на 4–16 человек. Python 3.12 + aiogram 3.31, SQLite, long polling. Платный ИИ и внешняя генерация текста не нужны: эпилог формируется из фактической истории, ресурсов, состава и исхода проверок.

**Статус:** код реализован и проверен автоматическими тестами и автономными симуляциями. Для размещения на Amvera добавьте `BOT_TOKEN` в секреты приложения; база сохраняется в `/data`. Токен не хранится в исходниках. GitHub Actions успешно выполнил 77 тестов, проверку контента, сборку Docker и загрузку контента внутри контейнера. Запуск на аккаунте Amvera ещё не выполнен.

## Самый короткий запуск с iPhone на Amvera

1. В [@BotFather](https://t.me/BotFather) отправьте `/newbot`, выберите название и свободный username с окончанием `bot`. Скопируйте токен. В `/setjoingroups` разрешите добавление в группы. Privacy mode можно оставить включённым: игре достаточно команд, кнопок и служебных сообщений.
2. В Amvera создайте приложение с Docker. Распакуйте ZIP в приложении «Файлы» на iPhone и загрузите **содержимое папки `bunker-blagoveshchensk`** в код проекта. `Dockerfile`, `requirements.lock`, `amvera.yml` и папка `bunker` должны оказаться в корне проекта, а не во вложенной папке.
3. В секретах/переменных приложения задайте:
   - `BOT_TOKEN` — токен из BotFather;
   - `DATABASE_PATH=/data/bunker.sqlite3`;
   - `ADMIN_IDS` — ваш числовой Telegram ID, можно заполнить после первого запуска, узнав его через `/id`;
   - `LOG_LEVEL=INFO` — необязательно.
4. Постоянное хранилище должно быть подключено в `/data`; экземпляр приложения — **один**. Домен, HTTPS и открытый порт боту не нужны.
5. Соберите и запустите приложение. В журнале должна появиться строка `Bot started: @ваш_username`.
6. Откройте бота → Start → «Создать комнату» → «Добавить в игровую группу». Выберите группу. Пригласите участников кнопкой «Пригласить друзей» либо групповой кнопкой входа.
7. Каждый из 4–16 игроков открывает личное приглашение и нажимает Start. Организатор выбирает таймер в ЛС и нажимает «Запустить партию».

Токен в репозиторий не добавляйте. Если бот уже работает на другом сервере, сначала остановите тот экземпляр. При ошибке `Conflict: terminated by other getUpdates` одновременно запущены две копии одного бота.

Документация платформы: [Docker](https://docs.amvera.ru/applications/configuration/docker.html), [постоянное хранилище](https://docs.amvera.ru/applications/storage.html). После пересборки каталог `/app` расходный, `/data` сохраняется. Entrypoint подготавливает каталог данных и затем запускает бота с uid 10001 без root-прав. Если платформа принудительно запускает контейнер от другого пользователя, каталог `/data` должен быть доступен этому пользователю на запись.

## VPS с Docker Compose

В каталоге проекта:

```bash
cp .env.example .env
# Заполните BOT_TOKEN и ADMIN_IDS в .env.
docker compose up -d --build
docker compose logs -f --tail=50 bot
```

Обновление: замените исходники, затем повторите `docker compose up -d --build`. Именованный том `bunker-data` сохраняет партии. **Не используйте `docker compose down -v`**, если нужны существующие данные.

Остановка: `docker compose down`. Входящие обновления Telegram при запуске намеренно не удаляются. Не запускайте несколько реплик long polling: [ограничение aiogram/Telegram](https://docs.aiogram.dev/en/latest/dispatcher/long_polling.html).

## Локальный запуск без Docker

Нужен Linux/macOS/WSL, Python 3.12 и доступ к Telegram API. iPhone самостоятельно сервером не служит.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock
cp .env.example .env
# Заполните .env
python -m bunker.bot
```

`requirements.txt` фиксирует прямые зависимости, `requirements.lock` — все проверенные runtime-зависимости. Игровой движок и симулятор не требуют aiogram для расчёта партии. Блокировка файла защищает от двух локальных процессов с одной БД.

## Игровой цикл

1. Сбор в группе; секретные карточки только в ЛС. По коду: `/join КОД` в личном чате.
2. Акты 1–2: завязка, первые сведения о катастрофе. Пол и возраст публичны; полное собственное досье видно владельцу.
3. Акты 3–8: каждому по одному раскрытию за акт, затем сюжетная сцена, решение группы, обсуждение и необходимые тайные исключения.
4. Биография открывается по выбору с акта 4, моральный поступок с 5, отношения с 6, секрет с 7. Автоматический ход по таймеру никогда не раскрывает секрет или связь.
5. Исключение: один голос от каждого активного, голос за себя запрещён, менять принятый голос нельзя. При первой ничьей — защита и повтор, при второй — жребий. Промолчавший до срока воздерживается. Промежуточные итоги не публикуются.
6. Акт 9: дверь закрывается, доступны последние особые условия. Акт 10: проверка выживания, судьба каждого, хроника важных решений и личный результат скрытой цели.

Мест — `ceil(число игроков / 2)`. До акта `a` (3–8) планируется `floor((N − мест) × (a − 2) / 6)` исключений; добровольно ушедшие учитываются. На больших составах в одном акте может быть несколько голосований. В партии ровно десять актов, число голосований динамическое.

Особое условие применяется один раз, даёт небольшой ресурсный бонус и не отменяет голосование. «Скрытый талант» помогает сцене только после раскрытия соответствующей карточки. Односторонняя связь не отправляется другому человеку. Независимо выданные биографии, секреты и профессии могут создавать противоречивый образ — это повод для истории, а не гарантия реалистичной биографической хронологии.

Ресурсы: вода, еда, энергия, медицина, мораль, прочность — шкалы 0–100, а не реальные литры и дни. Карточки здоровья описательные: диагнозы не дают автоматического штрафа и не являются медицинским руководством.

### Таймеры и управление с телефона

| Режим | Обычная фаза / личное раскрытие | Обсуждение |
|---|---:|---:|
| Быстрый | 40 секунд | 80 секунд |
| Стандартный | 90 секунд | 180 секунд |
| Длинный | 180 секунд | 360 секунд |
| Без таймера | По кнопкам участников | Готовность всех активных |

Часы показаны на момент формирования сообщения, «Обновить панель» пересчитывает остаток. Бот не редактирует сообщение каждую секунду. Ничья и право защиты — отдельные фазы. В режиме без таймера молчащий участник должен вернуться или выйти из игры. Администратор может закрыть зависшую комнату; он не получает право тайно голосовать за других.

Основные кнопки: персонаж, цель, раскрытие, выбор события, голосование, особое условие, история, готовность, выход. В группе кнопка действия доставляет персональное управление в ЛС; бюллетень никогда не размещается в группе. Панели узкие, кнопки в 1–2 колонки, длинные тексты разделяются по лимиту Telegram.

Итого **1 150** основных записей по запрошенным категориям, **1 151** с дополнительной сценой. Ещё по 20 характеров, страхов, достижений и моральных поступков: **1 231 запись всего**. Возраст и пол генерируются отдельно.

Сценарии — художественный вымысел. В игре нет реальных адресов защищённых объектов, сведений о действительных происшествиях или инструкций по пересечению границы. Амур, Зея, Хэйхэ, мост, Игнатьево, Чигири, набережная, мороз, паводки и китайская техника определяют задачи и нужные знания, а не служат только декорациями.

Редактируйте JSON напрямую. `scripts/build_content.py` содержит авторский источник и **перезаписывает** JSON: после ручных правок его запускать не нужно. Добавление пакетов и схемы — в `docs/CONTENT.md`.

## Администратор

`ADMIN_IDS=123456789,987654321` → `/admin` в ЛС:

- активные комнаты, игроки, этапы;
- статистика завершённых партий;
- закрытие комнаты с подтверждением;
- включение/отключение дополнительных пакетов для будущих комнат.

Основной пакет обязателен. Выбор пакетов фиксируется при создании комнаты. Уже начавшиеся комнаты не меняются из-за переключения пакета. Администратору интерфейс не показывает чужие цели или секреты.

## Надёжность и ограничения

- SQLite WAL, транзакция «состояние + исходящие сообщения», журнал обработанных действий.
- Перезапуск сохраняет карточки, голоса, фазу, сроки, случайную последовательность и очередь доставки. После долгого простоя просроченная фаза заканчивается один раз; следующей даётся полный интервал.
- Повторный callback не повторяет действие. Старые кнопки и неправильный порядок отклоняются. Принятый голос не меняется.
- Ошибки сети и Telegram 429 повторяются с задержкой. Невозможные к доставке сообщения помечаются отдельно; исключение одной доставки не останавливает другие чаты.
- Постоянная блокировка бота в ЛС означает выход участника в начатой партии. Разблокировка возвращает доступ к истории, но не отменяет исключение. В лобби игрок остаётся неготовым.
- Служебное сообщение об уходе из группы тоже обрабатывается. Для этого бот должен получать соответствующие Telegram-обновления. Удаление бота из группы сообщает об этом организатору в ЛС; таймеры продолжаются.
- При уходе/исключении организатора роль передаётся первому оставшемуся активному. Роль не даёт дополнительных голосов.
- Удалённые сообщения не мешают: бот отправляет новые панели, старый message_id не нужен.
- Доставка исходящих сообщений — **at least once**: при аварии после отправки в Telegram, но до подтверждения в SQLite возможно дублирование сообщения; игровое действие при этом не повторится.
- Нет обещания бесконечно работающего сервера, глобальной высокой доступности или большой нагрузки: версия рассчитана на один процесс и небольшое сообщество. PostgreSQL потребует нового адаптера репозитория и миграции, а не смены одной переменной.
- Telegram может ограничивать частоту сообщений. Устаревшие ожидающие панели объединяются; уже отправленные остаются в истории чата.
- Бот не определяет, кто убедительнее выступил, и не модерирует обычные сообщения: обсуждение проводят сами игроки.

## Резервные копии и перенос

Копировать только `bunker.sqlite3` во время работы небезопасно из-за WAL. Используйте SQLite backup:

```bash
python scripts/backup.py data/bunker.sqlite3 backups/bunker-2026-10-01.sqlite3
```

На VPS скрипт можно запускать из хостовой среды с доступом к тому либо временного Python-контейнера. В Amvera остановите приложение и скачайте все файлы каталога Data; для переноса предпочтительна согласованная копия через SQLite backup. Восстанавливайте БД при остановленном боте. Состояние содержит личные игровые секреты: резервную копию нельзя выкладывать публично.

## Архитектура

```text
bunker/
  bot/          запуск, жизненный цикл и права контейнера
  engine/       чистая игровая логика и эпилог
  states/       фазы, акты и правила раскрытия
  database/     SQLite, транзакции и outbox
  content/      загрузчик и независимые JSON-пакеты
  keyboards/    inline-панели Telegram
  handlers/     команды и проверка происхождения callbacks
  services/     сценарии приложения, доставка и безопасные представления
```

Описание модели и автомата: `docs/GAME_DESIGN.md`. Лицензия кода и оригинального контента: MIT. Проект не заявляет связь с авторами какой-либо коммерческой настольной игры.
